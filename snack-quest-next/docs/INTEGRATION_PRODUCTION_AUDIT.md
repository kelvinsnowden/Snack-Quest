# Integration production audit — second pass (internal)

**Internal.** Not part of the manufacturer handoff package.

Written before any code in this pass changed, from reading the code,
not the previous reports. Each gap has a severity (S1 money/stock/
isolation, S2 scale/operability, S3 hygiene), the fix, and — once done —
the evidence. Areas the audit found sound are listed at the end.

| ID | Sev | Area | Gap found | Fix | Evidence |
|---|---|---|---|---|---|
| G-01 | S1 | Rate limiting | Falls back to a **per-process in-memory** store when KV is unset *or* when KV errors, so in a serverless deployment limits multiply by instance count. No manufacturer-wide limit | Store chain KV → Firestore (atomic counters, sharded for high-volume keys); in-memory only under the test runner by explicit opt-in; manufacturer-wide rule | `rateLimitDistributed.test.ts` |
| G-02 | S1 | Credentials | A **suspended manufacturer's keys still authenticate** on every machine endpoint (only webhooks checked status; dispatch was refused, but reports and polls were accepted) | Manufacturer status checked on every authenticated request (cached with the credential), `403 manufacturer_suspended` | `credentialLifecycle.test.ts` |
| G-03 | S1 | Outbound credentials | Snack Quest's credentials for manufacturer APIs come from **two global environment variables** — one manufacturer, one environment, no rotation, no audit; base URL unvalidated (SSRF) | `manufacturerApiCredentials`: encrypted, per manufacturer × environment, versioned rotation with overlap, revocation, audit log, write-only admin UI; adapters resolve through a server-only credential service; https-only, private-address-refusing base URLs | `outboundCredentials.test.ts` |
| G-04 | S1 | Outbound HTTP | (a) timeout cleared once headers arrive — a stalled body hangs the dispense; (b) **409 on the idempotent vend is treated as a refusal → refund** though the vend may exist; (c) 2xx with a body that isn't the contract's `{accepted:true}` is treated as accepted; (d) 408/429 never retried, `Retry-After` ignored; (e) response size unbounded | Whole-exchange deadline incl. body; 409/malformed/partial → unknown (pull resolves); 408/429 → provably unprocessed, retried with the same idempotency key within a budget; 1 MB response cap | `manufacturerHttpResilience.test.ts` (real sockets) |
| G-05 | S1 | Payments | **Payment initiation is not idempotent**: a retried kiosk request sends a second STK push; the customer can approve both | `Idempotency-Key` (or same machine + phone + cart within 2 min) returns the original payment instead of a new push | `dispenseStateMatrix.test.ts`, `vendOutcomeSafety.test.ts` |
| G-06 | S2 | Crons | A single unexpected error **aborts a whole sweep**; run records are written only at the end, so a crash or platform timeout leaves no trace; no overlap guard; a failed or missing run alerts nobody | Per-item isolation with error counts; `runScheduledJob` writes a `running` record first, holds a lease, finishes with processed/errors/duration; failed runs and overdue jobs raise `job_failure` alerts | `scheduledJobs.test.ts` |
| G-07 | S2 | Slot mapping | No mapping history; slots can be configured with a product that doesn't exist or a non-positive price | Append-only `slotMappingHistory`; price (≤ KES 100,000), capacity (≤ 1,000) and slot-id validation. Product existence isn't validated in `configureSlot`: it has no staff route yet, so nothing sets a slot's product through it; validate there when one is added | `slotMappingAndInventory.test.ts` |
| G-08 | S2 | Inventory | An **older inventory report** (delayed, reordered) is compared as if current, raising false mismatches after a restock | A report observed before the last applied one is `stale: true`; a slot whose ledger moved after the report was observed is listed in `supersededSlots`, not compared | `slotMappingAndInventory.test.ts` |
| G-09 | S2 | Time | `occurredAt` without an offset is parsed as server-local time | Offset-less timestamps are not believed (receipt time used); poll returns `serverTime`; documented | `commandPollingSemantics.test.ts` |
| G-10 | S2 | Alerting | No alerts for repeated dispense failures, authentication-failure bursts, an outbound manufacturer API being down, abnormal timeout rate, credentials expiring / grace ending / revoked, webhook rejection streaks, failed or overdue jobs | Condition alerts with deduplication (one open alert per condition, auto-resolving); critical-alert SMS at most once an hour per condition | `lib/integrationAlerts.test.ts`, `services/integrationAlerts.test.ts`, `scheduledJobs.test.ts` |
| G-11 | S2 | Admin console | No credential audit history, no outbound credential management, no onboarding checklist that shows which step is manual, no certification-run history | Added to the manufacturer page (credential history, outbound credentials, onboarding checklist, certification runs) and machine page (API probe, harness run) | `credentialLifecycle.test.ts`, `manufacturerOnboarding.test.ts` |
| G-12 | S2 | Certification | A model can be certified from **manual checklist entries alone** — the automated harness is optional | New required checklist item `contract_suite`, recordable only by a CERTIFIED harness run against a manufacturer machine | `certificationHarness.test.ts` |
| G-13 | S2 | Contract suite | Nothing a manufacturer (or we, per candidate) can run to get a pass/fail report | `npm run test:manufacturer-contract` (inbound, harness against a pluggable subject) and an outbound API probe mode | `manufacturerContract.test.ts`, `certificationHarness.test.ts` |
| G-14 | S1 | Tenant isolation | Owner-route isolation is tested per feature, not exhaustively | Route sweep: every owner route called as owner A with owner B's ids, with no session, and with a manufacturer key | `ownerIsolationSweep.test.ts` |
| G-15 | S2 | Simulator | No restart (volatile state lost but executed-command record kept), no Model A webhook sender | Persistent executed-command store + `restart()` (flash kept or lost); duplicate delivery and lost-response faults; webhook-sending manufacturer cloud | `v1SimulatorScenarios.test.ts` |
| G-16 | S2 | Webhooks | Security cases spread over several files; modified body, expired timestamp and cross-manufacturer untested together | One matrix | `webhookSecurity.test.ts` |
| G-17 | S2 | Replay | No test that two identical signed requests sent concurrently can't both succeed | Concurrency tests on both nonce stores | `nonceConcurrency.test.ts` |
| G-18 | S3 | Docs | "v1 supported for at least 12 months" is an unagreed commitment; no manufacturer guide or certification doc; OpenAPI examples not validated; implemented vs future not separated | Compatibility policy instead of a date; handoff package (spec, OpenAPI, integration guide, certification guide, C signing reference); implemented / manufacturer-specific / not-yet-available separated; example validation in the contract test | `machineApiContract.test.ts`, `referenceSdks.test.ts` |
| G-19 | S2 | Scale | No concurrency test of many machines at once or of two customers buying the last item | Emulator concurrency tests with measured numbers (not production capacity claims) | `concurrency.test.ts` |

Verified sound in this pass (no change): nonce claimed only after signature verification (a request without the secret can't burn a nonce); atomic nonce `create()`; dispense claim-before-act; compare-and-set money transitions; environment and manufacturer isolation on every v1 lookup; secrets encrypted at rest (AES-256-GCM) and shown once; list APIs return an explicit field list; logs redacted; Firestore rules deny client writes on every integration collection; owner health goes through adapters and never returns manufacturer fields; slot mapping changes are audit-logged and conflict-checked; dispense commands capture the manufacturer slot id at dispatch, so a later remap can't redirect them.

## Known limitations after this pass

Stated here so no report or document claims otherwise:

| Limitation | Consequence | Mitigation today |
|---|---|---|
| Refunds are **recorded**, not executed through M-Pesa | A customer owed money waits for staff to send it | Sales owed a refund show on the machine page and orders; the deep reconciliation raises `refund_owed_too_long` after 24 h; a late "dispensed" report on a sale still owed a refund goes to review |
| No stock reservation at checkout | Two customers can pay for the last item; the second is refunded (`no_product`) | Proven safe (one dispense, one refund) by `concurrency.test.ts`; documented to manufacturers |
| KV nonce mode during a KV outage | A request whose nonce was stored only in KV could be replayed once inside the 10-minute window | Firestore nonce mode (the default) has no such gap |
| DNS rebinding between the public-host check and the outbound fetch | A manufacturer-controlled hostname could re-resolve to a private address between check and use | Production hosts are re-resolved and checked at call time; link-local/metadata always refused; residual window remains |
| A connect timeout is classified "maybe delivered" | A vend that provably never left can go to review instead of refund | Conservative by design (never a wrongful refund); resolved by the pull lookup |
| No external watchdog unless one is configured | If the scheduler itself stops, nothing inside Snack Quest notices | `/api/cron/health` returns 503 when a job is overdue or failing: point an external uptime monitor at it |
| Model A cannot reach production | `reference_http` is sandbox-only and the harness is Model B-shaped | Documented to manufacturers; a production adapter + harness extension per Model A manufacturer |
| Certification needs all three optional control endpoints | A manufacturer that can't implement hold / retransmit / request-log can't be certified | Documented as required in `MANUFACTURER_CERTIFICATION.md` |
